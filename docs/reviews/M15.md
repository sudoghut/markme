# M15 —— 第二意见必须比到被标记的每一天

规范：`docs/create-project.md` §7.2 闸门 4。分支 `m15-second-opinion-coverage`。

## 一、起因

M14 闸门 A 第 2 轮发现的 pre-existing SERIOUS（`docs/reviews/M14.md` P1）：`cross_source_gap`
按 `(symbol, date)` 内连接。Stooq 有历史、还没有当天（夜里的常态）时，被标记的当天那行在连接里消失，
`worst` 只在历史上算出 ≈0 →「备源同意」→ 脏行留在 frame 里；截止之后或次日定稿跑里以
`preliminary=False` 写进库、进当天指标与榜单。状态是 `partial`、会告警，但毒数据照写 ——
违反闸门 4「备源不同意（或拿不到）→ 剔除」。

用户确认：M14 合并后接着开 M15，两道闸门干净后自动合并。

## 二、实现

- `SanityIssue.dates`：每条问题牵涉的**所有**日子。OHLC / `adj_close<=0` / `volume<0` 是那几行；
  跳变是**一对**（前一天与被记下的那一天）—— 跳变说不清是哪一根坏了。公司行动日放行的那一对不记。
- 第二意见：被标记的日子必须都在比对里、且 `rel_diff` 不是 NaN；否则 `worst = NaN` →
  比不出来就不信 → 剔除。说不出日子的问题（`dates` 为空）同样按比不出来办，
  免得日后新加一条检查忘了填、静默退回内连接的老行为。
- 规范文本：`docs/create-project.md` §7.2 闸门 4 新增一条。
- 测试 11 条：`test_fetch.py` 的 `TestIssueDates`（4）与 `TestSecondOpinionMustCoverTheFlaggedDays`（5，
  含 M14 闸门 A 的原样复现、跳变一对缺一边、NaN 不算比到、真暴跌照写、无日期不信）；
  `test_preliminary.py` 的 `TestSecondOpinionEndToEnd`（2，22:45 与次日定稿跑，Stooq 有历史没有当天）。

**变异测试**（逐条还原，跑 preliminary / fetch / run_once / run_daily 四个测试文件）：8 个变异体全部被抓
（去掉覆盖检查、去掉无日期保护、NaN 算比到、跳变只记后一天、三种检查各不记日期、跳变不再放行公司行动）。

**行为变化（有意）：** 一次真实的暴跌若 Stooq 当晚还没有那一天，现在会被剔除、记 `partial`；
等 Stooq 有了那一天，下一跑比对通过、照写。以前是「只比历史就放行」。这正是「比不出来就不信」。
