## 两处推翻了本轮自己的决定，单独记账

### 1. `sr-only` 加了又撤

第 1 轮的 A5 说得对：删掉虚线后这条语义只剩 `title`，而 `title` 在触屏上等于不存在。
于是我加了 `<span className="sr-only">（预告值）</span>`。

第 2 轮推翻它的理由比 A5 更硬，而且是**用本次改动自己的前提**推翻的：既然
「几乎每枚标签都是预告值」，那 `sr-only` 就是把整列噪音从视觉通道搬进朗读通道，
而且只搬了一半（「已确认」没有对应物）。用户的判断是这条区分**不值得一个通道**，
换个通道加回来不是尊重那个判断，是绕开它。

`RepoLink.tsx:13` 那条先例也不适用：那是为**上下文变更**（在新标签页打开）写的，
焦点落到新上下文之后才被告知是具体危害；这里是静态 `<span>` 上的一个数据标注，
不改变任何上下文。把一条为特定危害写的规则推广成「凡 `title` 必配 `sr-only`」，
是在放大先例。

**残留的代价如实写在 `/methodology` 的「已知局限」里**：「标签上不做视觉区分
—— 桌面端悬停可看，触屏上看不到。」第 3 轮另记一笔：纯键盘用户同样拿不到
（`title` 挂在不可聚焦的 `<span>` 上），这句话没提，但它说的两种情形都为真、
没有虚假承诺。

### 2. 改了一个已应用到生产的迁移文件的注释

`supabase/migrations/0001_init.sql:67` 是 schema 里**唯一**解释
「`is_estimated` 为什么不能有 `default`」的地方，而它的论据落在「前端的虚线」上。

有 agent 建议撤回，理由不是风险而是「签入的 0001 就是当初跑过的那份」这条性质。
**没有采纳**，理由：

- 安全性独立复核过两遍：`.github/workflows/` 无任何一步跑 migration
  （只有 `heartbeat.yml` 的 `pg_dump` 打活库、`keepalive.yml` 跑 `invariants.sql`）；
  没有 `supabase/config.toml`、没有迁移状态表、没有 checksum；该文件**全文没有
  一条 `COMMENT ON`**，注释不进库，从这个文件重建的 schema 逐字节等价；
  读它做文本断言的 5 个测试都会先 `mask()` 抹掉注释。
- 改后的措辞（「会让前端的**标记**到处都是」）不再依赖任何具体视觉呈现，
  下次换呈现方式不会再腐烂一次。
- 留着一条指向不存在 UI 的论据，代价是有人据此认为「这条约束的理由已作废」
  而去放宽 `not null` —— 那是真会写出错数据的一条路。

### 3. 「芯片」→「标签」波及 5 个用户看不到的文件

有 agent 建议只改用户可见的 2 处。**没有采纳**：用户反对的是这个词本身
（「这里不翻译成芯片吧」），而注释里留着它会同样误导后来者 —— 在一个

`ruff format --check` 全绿。

连带成本一条，如实记下：「标签」在本仓库是个**过载词**。
`widgets.tsx` 里既有「未显著微标签」又有「倒计时标签」，`RepoLink.tsx` 里是

（指**表头文案**）因此产生了新歧义，已改写成「表头文案和结果正好相反」。

## 判定为不修的，及理由

- **`estimated === null` 时 `title` 输出「已确认」**（把「不知道」说成「已确认」）。
  pre-existing，且**不可达**：`pipeline/metrics/events.py` 里
  `days_to_next_*` / `next_*_date` / `next_*_is_estimated` 全部由同一个
  `nxt_e` / `nxt_d` 派生，`nxt_e` 非空 ⇒ `is_estimated` 必非空；
  `supabase/invariants.sql` 把这 8 列当**一组**查，历史行与 `ok_events_stale`
  那一跑都是整组 NULL。三个 agent 各自独立报过又各自独立判定不可达。
- **`_bracket` 里 `last` 那一侧的 tie-break 对任何输出字段零影响**：
  `EventDistances` 没有 `last_*_is_estimated`，`days_since_*` 只看 `event_date`。
  pre-existing，本次只动了它上面的注释。记在这里是为了**下一轮不要再报一遍**。
- `config/metrics.yaml` 的 `estimated_flag` + `pipeline/config.py` 的校验 +
  `web/lib/config.ts` 的类型声明：`countdown_chip` 这个 widget 从未被
  `PoolTable` 分发过，所以这三者在**本次改动之前**就没有前端消费者。
  不是本次引入的死代码，不在本轮范围内。
