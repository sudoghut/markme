## 闸门 A — review agent

**3 项 SERIOUS，全部在 `ci.yml`，而且每一条都意味着 CI 并没有在执行它自己注释里声称的事。**

| # | 发现 | 处置 |
|---|---|---|
| S1 | **`uv sync --frozen` 的语义与注释正好相反。** `--frozen` 是「跳过 up-to-date 检查、照用 lock」；`--locked` 才是「lock 与 pyproject 不一致就失败」。原注释写的是后者的行为 | 已修 → `--locked`。**并实测验证**：往 pyproject 加一个依赖而不重新 lock，`--frozen` 退出 0（静默通过），`--locked` 退出 1 |
| S2 | **gitleaks-action 缺 `GITHUB_TOKEN`，在 `pull_request` 路径上是无条件 `process.exit(1)`**（它要靠 API 取 PR 的 commit 列表来定扫描范围）。而 `AGENTS.md` 规定所有改动走 PR —— 第一个 PR 就会红，且永远合不了 | 已修 → 注入只读的 `secrets.GITHUB_TOKEN`（在 `permissions: contents: read` 之下它也是只读的），并关掉 `GITLEAKS_ENABLE_COMMENTS` |
| S3 | **gitleaks 从未扫过全历史。** action 自己按事件类型决定范围：`push`/`pull_request` 只扫 diff，**只有 `workflow_dispatch`/`schedule` 才走全库扫描**。而 `on:` 里两者都没有 → `fetch-depth: 0` 完全是摆设，注释「全历史扫描，不只扫 diff」是假的 | 已修 → `on:` 增加 `workflow_dispatch` + 每周一次 `schedule` |

**MINOR / NIT 一并采纳**：`PYTHON_VERSION` 声明了但没有任何消费者（CI 实际用的是 runner 自带解释器，而
`uv.lock` 带 `python_full_version` 解析标记，换解释器会装出不同包集合）→ 传给 `setup-uv` + 加 `.python-version`，
并把 `requires-python` 收紧到 `>=3.13`（原来声明的 3.12 支持从未被测过）；
`.gitignore` 漏了 `supabase/.temp/`（M3 的 `supabase link` 会在里面写 `pooler-url`，可能含连接串）、
`build/`、`dist/`、`.vercel/`、`.claude/settings.local.json`；
所有依赖下界都是过时的 `>=`，而 `uv lock` 已经跨了四个大版本（yfinance 0.2→1.7、pandas 2.2→3.0、mypy 1→2…）
→ 下界改成实测跑过的版本，两个「非官方 API」的包加上界；
ruff 的 `exclude` 会**替换**默认排除表 → 改 `extend-exclude`；
`per-file-ignores` 里的 `S101` 是死配置（`S` 根本没在 `select` 里）→ 打开 `S`（bandit），
让它变成真的豁免；版本号写在三处而冒烟测试比的是两个字面量（永远相等，测不出漂移）
→ `[tool.hatch.version]` 单一来源 + 测试改为与 `importlib.metadata` 比对；
缺 `dependabot.yml`（§8.1.1「配套三件事」之二）与 `BACKLOG.md`（§14）→ 补上；
`pytest-cov` 声明了却没人用 → 移除并记入 BACKLOG，M2 再接。

| 假设 | 结果 |
|---|---|
| `auto_adjust` 默认为 `True`（§3.0 规则 4 的警告成立） | ✅ 确认 |
