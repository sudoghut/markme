# M16 —— 利率政策：目标区间、加息/降息、下次 FOMC、美债收益率

规范：`docs/add-rate-policy.md`。分支 `m16-rate-policy`。

## 一、起因与范围

用户要求评估并实现「加息 / 降息」信息的展示。范围只取**已发生的事实**，不做市场预期概率
（没有免费、权威、有 API 的来源；自己用期货反推时口径一错读数就是错的）。

数据源逐个实测过（2026-11-23）：纽约联储 EFFR 接口（每行自带目标区间）、财政部 Par Yield Curve CSV、
美联储 FOMC 日程页面（HTML，无 API）。**不用 FRED**：纽约联储的接口已带目标区间，少一个 key、
少一份第三方条款。纽约联储条款要求再发布时带指定声明，原文已核对并写进方法论页。

PR 部分（与本里程碑同一轮会话处理）：`#37/#38/#39` 单独 rebase 合并；`#29/#34/#35/#36/#41` 由 `#42`
一次升完并合并（它们都改 `uv.lock`，逐个合会互相冲突；`#36` 单独升 pandas 3.1 会红，因为
`pandas_market_calendars` 在 `days_at_time` 里用了已弃用的 `Series.dt.weekday`，按 BACKLOG 的约定
加了一条**定向**警告放行）。原五个 PR 已带说明关闭。

## 二、实现

- 独立管道 `pipeline/run_macro.py` + `.github/workflows/macro.yml`，不碰 `run_daily`；三个来源互相独立，
  失败的来源不动库里的旧数据；结果记进 `private.macro_fetch_state`。
- 解析器（`pipeline/macro/{nyfed,treasury,fomc}.py`）宁可拒收、不可猜；FOMC 页面的 `notation vote` 与
  `Monetary Policy Strategy Meeting` 明确识别后跳过，不认识的行形状整次拒收。
- 加息/降息只在 Python 里判一次（`Decimal` 差分），落成 `change_kind` / `change_bp`；前端只读。
- 迁移 `0004_rate_policy.sql`（+ 回滚）：沿用 0001 的最小权限模式。不变式 22 → 27。
- 前端：窄条软失败（`lib/ratesData.ts` 永不抛）；判断逻辑全在 `lib/rates.ts`，用 Node 内置 `node:test`
  测（前端此前没有任何自动化测试），CI 的 web job 新增 `npm test`。

## 三、真 Postgres 上的验证

审查者指出 SQL 不变式和迁移没有任何测试连库跑过。本机没有可用的 Docker 守护进程，改用临时目录里的
内嵌 Postgres（`pgserver`，不进仓库依赖，用完已删）：

- 迁移 0001–0004 依次应用成功；
- 以 `pipeline_writer` 身份用**真实网络**端到端跑 `run_macro`：1224 行利率（识别出 2022 年起 18 次变动，
  含 2022-03-17 的首次加息 +25bp 与 2026-09-17 的加息）、1416 行收益率、23 场会议；二次运行行数不变（幂等）；
- 27 条不变式以 writer 身份 0 违规；
- **逐条注入错数**（标了加息但区间没变 / 区间变了漏标 / 方向标反 / 最新 EFFR 离谱 / 收益率成小数形式 /
  没有未来会议 / 会议重复 / 目标区间停摆 / 收益率停摆），对应断言都恰好触发；
  （第一次注入脚本把注入放在未提交的事务里、检查用另一个连接，全部「未触发」——那是脚本的毛病，
  不是断言通过；改成同一事务后才得到上面的结果。）
- 权限：anon 能读、不能写、看不到 `private`；writer 不能 DELETE 两张事实表、不能 UPDATE 日程表。

另外用本地假 PostgREST 跑了构建产物，四种态（正常 / 陈旧 / 表为空 / **表不存在**）页面都是 HTTP 200，
价格表照常渲染；这不是自动化测试。

## 七、部署（需要人手动做的两步）

1. 在 Supabase SQL Editor 里以 owner 身份执行 `supabase/migrations/0004_rate_policy.sql`。
2. 合并后手动触发一次 `macro` workflow（`workflow_dispatch`）回填整段历史。

**迁移没跑就合并的后果**（设计上是软失败，不是故障）：页面窄条显示「利率数据暂不可用」，价格表照常；
`macro` workflow 与 `keepalive` 的不变式会变红，直到迁移与回填做完。
