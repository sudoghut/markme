**MINOR 全部采纳**：`_as_number` 会对 `Decimal` / `np.int64` / `pd.NA` **抛异常** ——
而 psycopg 还给 Postgres `numeric` 的正是 `Decimal`，`alpha_t_stat` 就是 `numeric`，
等于「空值 fail closed」这条承诺对真实数据不成立（→ 收敛成 `None`，且求值期**绝不抛**：
一个「要不要打灰」的判断没资格让整页渲染失败）；
`dim_when: "alpha_t_stat"` 被接受而其真实语义是「t 值恰好为 0 时打灰」
（→ 根节点必须是比较或布尔运算）；`check_columns_match` 传整表列会失败，
逼调用方维护第二份「哪些是结构列」的名单（→ `STRUCTURAL_COLUMNS` 内置）；
`composite` 可配但接不上，而 §4.1 列出的 `score_metric: composite` 反而被拒
（→ 放行保留值 + 选了必须开、开了必须选 + 权重 `ge=0`，因为公式是减号，
负权重会把风险惩罚反转成风险**奖励**）；`enabled` 软删除无测试，
把 `enabled_symbols` 写成 `return self.symbols` 全套照样绿（→ 补测试）；
fail-closed 测试全写死字面量，把 YAML 里的 `abs` 删掉测试照样绿而每行负 alpha 都不再打灰
（→ 关键测试改为从**真实配置**驱动）；`parsed_dim_when` 是死代码且是唯一会破坏
`ConfigError` 设计的地方（`DimExprError` 当时继承 `ValueError`）（→ 删除 +
`DimExprError` 改继承 `ConfigError`，为此把 `ConfigError` 抽到 `pipeline/errors.py` 解环）；
一元运算符可无括号无限叠加而 CPython 抛的不是 `SyntaxError`（→ 捕获 + 长度上限）；
`1e400` 解析成 `inf` 使 `abs(x) < 1e400` 恒真（→ 常量必须有限）；
`widget` / `format` 是自由字符串而前端直接读这份 YAML、没有 codegen 步骤（→ 闭集合 + 正则）。

### 测试在修复过程中抓到一个真 bug

补 `Decimal` 支持时，新测试立刻失败：`Decimal("0.5")` 被判成「打灰」，
而 `0.5 < 0.3` 应为 False。原因是 **`Decimal` 并没有注册为 `numbers.Real`**
（它只注册了 `numbers.Number`），于是落进兜底分支被当成空值。
若没有这条测试，结果会是**每一格都打灰，而「fail closed」看起来还在正常工作**。
